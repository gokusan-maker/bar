# バー予約自動反映アプリ

**複数のお店で使えます。** オーナーが `/signup` でお店を登録すると、お店ごとにオーナー・スタッフ・お客様・予約・売上・メニュー・SNSの接続が分かれます。運営（販売する側）は `/operator` で登録されたお店の一覧を見て、利用を止めたり再開したりできます。

SNS（LINE・Instagram）のメッセージで届いた予約を自動で読み取り、空きを確認して返信し、Googleカレンダーに反映するアプリです。
要件は [`docs/requirements.md`](docs/requirements.md)、画面のイメージは [`docs/mockups/`](docs/mockups/) を参照してください。

## 使うSNS
| SNS | 位置づけ | 受付のしかた |
|---|---|---|
| **LINE** | メイン | トークで届いた予約を自動で読み取り・返信（ボタンで答えられる）。リマインドもLINEで送る。友だち追加URLを設定すると、予約フォームと空き状況の投稿でLINEへ案内 |
| Instagram | サブ | DMを自動受付（Metaの審査後）。プロフィールに予約フォームのリンク |
| X（Twitter） | サブ | プロフィールと投稿に **X用の予約リンク**（`/reserve?from=x`）を載せる。このリンクからの予約は「X」として集計・バック対象。XのDMの自動受付は、X APIが有料（2026年2月から従量課金）のため使っていない |

## できること

| 機能 | 内容 |
|---|---|
| 予約の自動受付 | 「土曜の9時から2名、山田です」のような文章から日時・人数・名前・要望を読み取り、空いていれば自動確定して返信 |
| 聞き返し | 日時・人数が足りなければ自動で質問し、複数回のやり取りで予約を完成させる。LINE・Instagramでは「明日」「21時」「2名」などのボタン（クイックリプライ）も付け、空いている時間だけを選択肢に出す |
| 満席時の代案 | 同じ夜の近い空き時間を最大3つ提案 |
| 変更・キャンセル | 「22時に変更できますか」「キャンセルします」に対応し、カレンダーも更新・削除 |
| 店主の承認 | 大人数・貸切・読み取りに自信がないものは「承認待ち」にして店主に通知。管理画面でワンタップ承認 |
| Googleカレンダー | 予約を予定として登録（仮予約は黄、確定は緑）。カレンダー上の休業・貸切の予定がある時間は受付不可 |
| 管理画面（スマホ対応） | 予約一覧、承認、手動登録（電話予約）、メッセージ履歴と手動返信、顧客メモ、設定 |
| リマインド | 前日のお客様にSNSで自動リマインド（毎日12時） |
| 売上の記録 | 来店ごとに「お酒・料金（チャージ/セット）・サービス料」を入力。予約から開くと人数×チャージとサービス料が自動で入る |
| 証拠の添付 | 伝票・レシートの写真やPDFを売上に添付。スマホの大きな写真は送信前に自動で縮小。中身を確認して画像・PDF以外は拒否 |
| 月のバック計算 | スタッフごとに「バック率○%・1組○円」を設定し、担当したお客様の売上全体（サービス料を含む）から月のバックを計算。CSVとPDF（印刷用の明細）で出力 |
| デザインのカスタマイズ | テーマカラー（琥珀・ボルドー・ネイビー・エメラルド・パープル・チャコール）、お店の電話番号、予約フォームのひとことを設定。ダークモード対応 |
| 今夜のまとめ | 予約一覧の先頭に、今夜の組数・人数・承認待ちと、時間ごとの席の埋まり具合を表示 |
| スマホ用の下部タブ | 予約・売上・お客様・メッセージ・設定をアプリのように切り替え |
| 店のカスタマイズ | 店の種類、席の構成（カウンター・テーブル・個室など自由に追加）、チャージ額、サービス料率、バックの対象（SNS経由のみ／全売上） |
| 紹介ページ | トップページ（`/`）でアプリの機能を紹介し、「お店を登録する」へ案内。登録・利用は無料 |
| 利用規約・プライバシーポリシー | `/terms`・`/privacy`。広告（AdSense）の Cookie の説明つき。お店の登録時に同意してもらう。運営者名・お問い合わせ先は `OPERATOR_NAME`・`CONTACT_EMAIL` |
| ホーム画面に追加 | スマホのホーム画面に追加すると、アイコンから全画面で開ける（アプリのように使える） |
| はじめの設定 | 新しく登録したお店のオーナーに、席・営業時間、LINEの接続、予約フォーム、メニュー、スタッフの招待までのチェックリストを表示 |
| 広告（Google AdSense） | `ADSENSE_CLIENT`・`ADSENSE_SLOT` を入れると広告を表示。場所は `AD_PLACES`（初期値は紹介ページと管理画面。お客様の予約フォーム・QR注文には出さない）。`/ads.txt` も自動で出す。印刷・PDFには出ない |
| お店の登録（複数店舗） | オーナーが `/signup` で店名・URL名・ログインID・パスワードを入れて登録すると、そのお店のオーナーになる。予約フォームは `/s/<URL名>/reserve`。LINE公式アカウント・Instagramはお店ごとに「設定 → SNSの接続」でつなぐ（Webhook URL はお店ごとに `/api/webhooks/line/<店舗ID>`）。`SIGNUP_CODE` を決めると、登録コードを知っている人だけが登録できる |
| オーナーとスタッフのログイン | ログイン画面は別々（オーナー `/owner/login`、スタッフ `/login`）。どちらも **LINEでログイン** でも **ログインIDとパスワード** でも入れる（オーナーのIDは設定画面で変更、初期値 `admin`。パスワードは `ADMIN_PASSWORD`）。オーナーは料金・メニュー・バック率・設定などすべてを決められる。スタッフは集客（空き状況の配信・投稿）、売上の入力（証拠写真つき）、お客様リストの登録・編集、メッセージの返信、予約の確認と来店チェック、注文の対応ができる（バックの金額・月の集計・設定・CSVは見えない） |
| スタッフの登録 | 「スタッフ」画面の登録用リンクを送ると、スタッフが「LINEで登録」（またはログインIDとパスワード）で申請し、オーナーが承認するとログインできる。パスワードで登録したスタッフも「アカウント」からLINEを連携できる。在籍を外す・ログインを止めると、すぐにログアウトされる |
| 開店前の通知 | 毎日17時に今夜の予約一覧を店主のLINEへ。Googleカレンダーに反映できなかった予約も自動で再同期 |
| 予約の編集 | 店主が日時・人数・名前・要望を変更。カレンダーも更新し、お客様に変更を連絡（任意） |
| 予約の集計 | 月ごとの受付数、SNS経由の割合、無断キャンセル率、キャンセル率、平均人数、曜日別の件数 |
| 予約フォーム | `/reserve` の公開ページ。InstagramのプロフィールやLINEのリッチメニューに載せると、DMを送らないお客様も予約できる（設定でオン）。電話番号で同じお客様をまとめ、SNS経由として集計。ボット対策の隠し欄と送信回数の制限つき |
| セットアップ診断 | 設定画面の「セットアップ診断」で、Supabase（未実行のSQLも検出）・Claude API・LINE・Instagram・Googleカレンダー・自動処理の設定を確認 |
| 集客の自動配信 | その日の空き状況を、決めた時刻（12時か17時）・曜日にLINEの友だち全員へ自動配信。空いている時間のボタン付きで、タップするとそのまま自動受付で予約が完了する。空きがない日は送らない。LINEの月の送信上限を超えそうなら送らずに店主へ通知。Instagramのフィードへの自動投稿（画像を1枚登録）も選べる |
| 誕生日のお祝い | お客様リストに誕生日が入っているLINEのお客様へ、誕生日の当日12時にお祝いを自動で送る（文面は自由に変更、{name} がお名前に。同じ年は1回だけ。2/29生まれはうるう年以外2/28） |
| 空き状況の投稿 | 予約状況から「本日の空き状況」の文面を自動で作り、コピーしてInstagramのストーリーズに貼れる。Xは「Xで投稿する」ボタンで文面入りの投稿画面を開ける（X APIは有料のため自動投稿はしない） |
| QRコード・URLでお酒の注文 | 店主がメニューと席を登録すると、席ごとのQRコード（印刷用ページあり）とURLができる。お客様はスマホで読み取ってメニューから注文。注文は「注文」画面（スタッフも使える・15秒ごとに自動更新）に届き、提供済み・取消を記録。会計で席の注文を売上（お酒の金額）に取り込める |
| お客様一覧 | 名前で検索、最終来店・来店回数・利用金額で並べ替え。担当スタッフ、今後の予約、無断キャンセル回数も表示 |
| カレンダーからの取り込み | Googleカレンダー上で予約の予定を移動・削除すると、毎日17時（またはボタン）で予約に反映し、店主に通知 |
| CSV書き出し | 予約・売上・お客様をCSVで書き出し（バックアップ・Excel用）。お客様の名前に含まれる数式は無効化 |
| 操作履歴 | 誰が（店主・スタッフ・お客様・自動）いつ何をしたかを記録。予約・売上ごとにも表示 |
| 個人情報の自動削除 | 保存期間（初期値24か月）を過ぎたメッセージを削除し、名前・SNSのIDを消す。売上金額と証拠写真は帳簿として残す |
| ログイン保護 | 15分間に同じ端末から10回（全体で100回）失敗すると、15分間ログインを止める |
| テスト送信 | SNSをつながなくても、管理画面からお客様役でメッセージを送って動作確認できる |

## まず動かしてみる（環境変数なし）

```bash
npm install
npm run dev
```

http://localhost:3000/admin/simulator を開き、「土曜の9時から2名でお願いします。山田です」などと送ってみてください。
環境変数がない場合は、データはメモリ保存・メッセージは簡易ルールで読み取り・カレンダー連携なしで動きます。

## 本番の準備

### 1. Supabase（データベース）
1. https://supabase.com でプロジェクトを作成
2. SQL Editor で `supabase/migrations/` のSQLを**ファイル名の古い順にすべて**実行（init → sales → audit → privacy → web_booking → x_channel → grants → staff_login → orders → customer_profile → birthday_greeting → staff_line_login → staff_login_id → multi_shop → multi_shop_customer_key）。表はすべて `bar` スキーマに作られるので、ほかのアプリと同じプロジェクトに同居できます。証拠写真用の非公開バケット `bar-evidence` もここで作られます
3. Project Settings → Data API → **Exposed schemas に `bar` を追加**して保存（しないとアプリから表が見えません）
4. Project Settings → API の URL と `service_role` キーを `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` に設定
5. `TOKEN_ENCRYPTION_KEY` に長いランダム文字列を設定（例: `openssl rand -base64 32`）

### 2. Cloudflare Workers にデプロイ（無料プランで商用利用可）
1. https://dash.cloudflare.com で無料アカウントを作る
2. **Workers & Pages → Create → Import a repository** で `gokusan-maker/bar` を選ぶ
   - Build command: `npx opennextjs-cloudflare build`
   - Deploy command: `npx opennextjs-cloudflare deploy`
3. 作成されたWorkerの **Settings → Variables and Secrets** に、[`.env.example`](.env.example) を見ながら値を入れる（パスワードやキーは「Secret」で）。`APP_BASE_URL` は `https://bar.<あなたのサブドメイン>.workers.dev`
4. もう一度デプロイ（Deployments → Retry、または GitHub に push）
5. 定期処理（毎日12時のリマインド、17時の予約一覧の通知など）は [`wrangler.jsonc`](wrangler.jsonc) の `triggers.crons` で自動登録される。`CRON_SECRET` の設定が必要

手元で Cloudflare と同じ環境を試す: `.dev.vars` に環境変数を書いて `npm run preview`

### 3. Claude API（メッセージの読み取り・任意）
**設定しなくても無料で動きます。** APIキーがない場合は、アプリに組み込んだ簡易読み取り（日付・時間・人数・名前、「週末」「夜9時」「1人増えます」「遅れます」などの書き方に対応）を使い、AIの料金はかかりません。より自由な書き方にも対応したい場合だけ、APIキーを設定してください（利用量に応じて料金が発生）。

https://console.anthropic.com でAPIキーを発行し `ANTHROPIC_API_KEY` に設定。
未設定でも動きますが、簡易ルールでの読み取りになります。API障害時も簡易ルールで受け付け、自動確定はせず承認待ちに回します。

### 4. LINE公式アカウント
1. LINE Developers でMessaging APIチャネルを作成
2. チャネルシークレット → `LINE_CHANNEL_SECRET`、チャネルアクセストークン（長期）→ `LINE_CHANNEL_ACCESS_TOKEN`
3. Webhook URL に `https://<ドメイン>/api/webhooks/line` を設定し「Webhookの利用」をオン
4. LINE Official Account Manager で「応答メッセージ」をオフ（自動返信が二重にならないように）
5. 店主への通知を受けたい場合は、店主のLINEで公式アカウントを友だち追加し、そのユーザーIDを `OWNER_LINE_USER_ID` に設定（ユーザーIDはWebhookのログか、テスト送信後のメッセージ一覧で確認できます）

### 4-2. LINEでログイン（任意・おすすめ）
1. LINE Developers の **同じプロバイダー** に「LINEログイン」チャネルを作成（Messaging API のチャネルとは別）
2. チャネルID → `LINE_LOGIN_CHANNEL_ID`、チャネルシークレット → `LINE_LOGIN_CHANNEL_SECRET`
3. 「LINEログイン設定」のコールバックURLに `https://<ドメイン>/api/line-login/callback` を登録し、チャネルを「公開済み」にする
4. オーナーは `/owner/login` にパスワードでログインし、「設定」→「LINEでログインできるようにする」で自分のLINEを連携（`OWNER_LINE_USER_ID` と同じLINEなら連携しなくてもログインできます）
5. スタッフには「スタッフ」画面の登録用リンクを送り、「LINEで登録」してもらって承認する

> 自動返信は無料の「応答（reply）」で送ります。承認結果・リマインド・手動返信は「プッシュ」なので、LINEの無料メッセージ通数に含まれます。

### 5. Instagram（任意）
1. Instagram をプロアカウントにし、Meta for Developers でアプリを作成（Instagram API・Instagramログイン方式）
2. `instagram_business_manage_messages` 権限のアクセストークン → `INSTAGRAM_ACCESS_TOKEN`、アプリシークレット → `INSTAGRAM_APP_SECRET`
3. Webhook のコールバックURLに `https://<ドメイン>/api/webhooks/instagram`、確認トークンに `INSTAGRAM_VERIFY_TOKEN` と同じ文字列を設定し、`messages` を購読
4. 一般のお客様のDMを受けるには Meta のアプリ審査が必要です

> Instagram はお客様の最後のメッセージから24時間を過ぎると返信できません。承認結果は24時間以内に送ってください。

### 6. Googleカレンダー
1. Google Cloud Console でプロジェクトを作り、Google Calendar API を有効化
2. OAuth同意画面を設定し、OAuthクライアントID（ウェブアプリ）を作成
3. 承認済みのリダイレクトURIに `https://<ドメイン>/api/google/callback` を追加
4. `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` を設定
5. 管理画面の「設定」→「Googleカレンダーと連携する」から店のGoogleアカウントでログインし、書き込むカレンダーを選ぶ

### 7. 最後に確認
デプロイ後、管理画面の「設定」→「セットアップ診断」を開き、「要対応」がないことを確認してください。

### 売上とバックの計算
- サービス料 =（お酒 ＋ 料金）× サービス料率。円未満切り捨て。手入力で上書きもできます
- バック =（お酒 ＋ 料金 ＋ サービス料）× バック率 ＋ 1組ごとの固定額（円未満切り捨て）
- PDFは「売上・バック」の「PDF」から印刷用の明細を開き、印刷画面で「PDFに保存」を選ぶ（スタッフごとの売上の内訳つき）
- バックの対象は、担当スタッフが付いていて、設定が「SNS経由のみ」ならLINE・Instagram（とテスト送信）から来た売上です
- 担当スタッフはお客様ごとに保存され、次回の売上入力で自動選択されます
- 金額は入力したまま（税込・税抜は店のルールで統一してください）。消費税の計算はしていません

### 設計メモ
- 時刻はすべてUTCで保存し、日本時間（UTC+9）で表示・判定します。深夜0時以降の来店は前日の営業日として扱います（例: 10/25の「1時」は 10/26 1:00）。
- 空き判定は「同時にお店にいる人数の最大値 ＋ 予約人数 ≤ 席数」で行います（席の割り当てはしません）。
- 同時に届いた予約で席を取り合った場合は、登録後に先着順で再確認し、後の方を取り消して満席の返信を送ります。
- 正のデータはアプリのDBで、Googleカレンダーは写しです。カレンダー上で予約の予定を移動・削除した場合は、毎日17時（または設定画面のボタン）でアプリに取り込みます。お客様への連絡は自動では行わず、店主に通知します。

### 集客の自動配信について
- LINEの一斉配信は、友だちの人数分の送信通数を使います（無料プランは月200通まで）。上限を超えそうな日は配信せず、店主のLINEにお知らせします
- Instagramへの自動投稿には、Metaのアプリに `instagram_business_content_publish` の権限が必要です。投稿画像はJPEGで、`/promo-image/…` の公開URLからInstagramが読み込みます
- 配信のボタンをタップすると「10/24 21:00から予約したいです」のような文が送られ、いつもの自動受付が人数・お名前を聞いて予約を確定します
